# 携帯電話位置情報・トリップデータ分析

`data.py` は指定されたZIP内のUTF-8 CSV.GZを展開せず読み込みます。
Python 3.10以上が必要です。追加ライブラリのインストールは不要です。
添付の定義書は列名・単位・交通手段コードの参照に使用しています。
同梱のプログラムは実行しません。

## 実行

### 交通手段別トリップ数を表示する別プログラム

`trip_modes.py` は既存の `data.py` を変更せずに追加した独立プログラムです。
完了済みの `full_output/analysis.sqlite3` を読み取り専用で参照し、
交通手段名・トリップ数・全トリップに占める割合をPowerShellに表示します。
ZIPの再分析は不要です。

```powershell
python trip_modes.py
```

`trip_modes_output/report.html` に表と棒グラフ、`trip_modes_output/trip_modes.csv`
に数値を保存します。同じ出力先で再実行すると、この2ファイルを更新します。
元の分析結果は変更しません。入力先を変える場合は次のように指定します。

```powershell
python trip_modes.py --input-dir full_output --output trip_modes_output
```

### 元データの分析

日付別の移動件数だけを確認する場合は、独立した `daily_trips.py` を実行します。
既存のプログラムと分析DBは変更せず、ZIPの再分析も行いません。

```powershell
python daily_trips.py
```

PowerShellに観測日・曜日・トリップ数・全期間に占める割合を表示し、
`daily_trips_output/report.html` に日別の表と棒グラフ、
`daily_trips_output/daily_trips.csv` に数値を保存します。
日付は移動開始日ではなく元データの観測日です。観測記録のない日は表示しません。
同じ出力先で再実行すると、この2ファイルを更新します。
入力先と出力先は `--input-dir full_output --output daily_trips_output` で変更できます。

PowerShellでこのフォルダに移動し、まず少量で動作を確認してください。
`python` が認識されない場合は、PythonをインストールしPATHを設定するか、
インストール済みのPython実行ファイルのパスを指定してください。

```powershell
python data.py "C:\Users\haeiw\Downloads\260320_cellphone_trip_data.zip" --limit 10000 --output sample_output
```

全30日分を分析する場合：

```powershell
python data.py "C:\Users\haeiw\Downloads\260320_cellphone_trip_data.zip" --output full_output
```

日付を絞る場合（両端を含む）：

```powershell
python data.py --start 2025-11-01 --end 2025-11-03 --output nov01_03_output
```

出力フォルダの `report.html` をブラウザで開いてください。レポートは外部通信なしで表示できます。
既存の `analysis.sqlite3` がある出力先は上書きしません。再実行には別の出力先を指定してください。
中断やエラーの後も同様です。途中結果を完成結果として扱わないでください。

## 出力

### 同一トリップ内の交通手段の混在を調べる

`mixed_trip_modes.py` は元ZIPを読み直し、従来と同じキー
（観測日・DAILYID・TRIP_RK・始終点時刻）に異なる交通手段が付いているケースを調べます。
既存DBは最初の交通手段しか残していないため、この分析では利用できません。
既存プログラム・既存結果は変更しません。

```powershell
python mixed_trip_modes.py
```

`mixed_trip_modes_output` に次の結果を保存します。

- `report.html`：重複して現れるトリップ数、交通手段が混在するトリップ数、距離・時間の平均、組み合わせ別件数、先頭30件の明細
- `mixed_trips.csv`：該当全トリップの手段・観測日・始終点時刻・直線距離km・所要時間分
- `mode_combinations.csv`：手段の組み合わせ別トリップ数
- `summary.json`：処理件数と集計値
- `mixed.sqlite3`：再確認用DB（識別子と時刻を含みます）

交通手段コードの混在と、具体的な交通手段（1〜8）が複数あるケースを分けて表示します。
「自動車＋不明」は前者だけ、「自動車＋徒歩」は両方に該当します。
不明・欠損だけの違いも混在に含みます。推定判定の不整合の可能性もあり、乗り換えの証明ではありません。
異なるトリップIDをまたぐ乗り換えは対象外です。
定義書のTRAFFIC_MODEは「代表交通手段」です。実際に乗り換えがあっても
1種類のコードしか付かない場合があり、混在0件でも複数手段の利用がなかったとは判断できません。

距離は始点・終点座標から計算する球面上の直線距離です。時間は始終点時刻差です。
どちらもトリップ全体の値で、手段別の距離・時間や実経路の距離ではありません。
同一キーの始終点座標は最初の記録を使います。有効な値がない場合は空欄にし、平均から除外します。
混在0件の場合は距離・時間の平均も算出しません。

全件の再読み込みに時間がかかります。先頭だけの確認は次の1行です。

```powershell
python mixed_trip_modes.py --limit 10000 --output mixed_sample_2
```

既存のDBがある出力先は上書きしません。中断後の再実行も別の `--output` を指定してください。

レポートでは、まず「何について分析しているか」を説明します。
対象は携帯電話の位置記録と推定トリップで、分析する問いは次の4点です。

- いつ観測が集中するか（日別・時間帯別）
- どの交通手段が多く観測されるか（ポイント数とトリップ数）
- どの地域に観測が集中するか（観測地点の地域コード）
- どの出発地と到着地の組み合わせが多いか（125mメッシュOD）

「結果から読み取れること・考察」では実際の集計値をもとに、
**確認できた事実 → 考えられる仮説 → 確かめるための追加分析**を表示します。
例えば、朝に位置記録が多くても、それだけで通勤が多いとは断定できません。
平日の出発時刻・目的地・取得頻度等を追加確認する必要があります。
月〜金と土日の比較は観測された日数で割った日平均と、延べ日別ID当たりの
トリップ数を併記します。祝日は自動判別しません。

### 既に分析を実行した場合

実行中のプログラムは変更前のコードで動いています。PowerShellに「完了」と
表示され、`full_output/summary.json` ができてから、次の1行を実行してください。
ZIPの読み直しをせず、保存されたDBから説明・考察付きのHTMLを再生成します。
CSVとDBは変更しません。

```powershell
python data.py --report-only --output full_output
```

その後 `full_output/report.html` を開き直してください。
サンプル集計の考察はそのサンプルだけの傾向であり、全件の傾向には一般化できません。

| ファイル | 内容 |
| --- | --- |
| report.html | 集計表、時間帯・市区町村別の棒グラフ（表は最大30行） |
| daily.csv | 日別ポイント数、日別ユニークDAILYID数、トリップ数 |
| hourly.csv | 時間帯別ポイント数 |
| traffic_points.csv | 交通手段別ポイント数、平均速度km/h、有効速度件数 |
| traffic_trips.csv | 交通手段別トリップ数、平均所要時間（分）、有効時間件数 |
| cities.csv | 観測地点の市区町村コード別ポイント数 |
| od_mesh.csv | 始点・終点125mメッシュの組み合わせ別トリップ数 |
| missing.csv | 各列の欠損件数・割合（分析対象ポイントが分母） |
| summary.json | 入力ファイル、対象期間、処理件数、不正値件数、件数制限等 |
| analysis.sqlite3 | 重複除去と集計に使う作業DB |

CSVはExcelで開きやすいUTF-8 BOM付きです。コード・メッシュをExcelで扱う際は
文字列として取り込むと先頭ゼロ等を保持できます。

## 集計の定義

- ポイントは入力CSVの行単位です。重複ポイントの削除は行いません。
- 日付・時刻はYEAR/MONTH/DAY/HOUR列を使用します。
- 日付や時刻が不正な行・列数が不正な行はスキップし、summary.jsonに件数を記録します。
- 空欄、null、nan（大文字小文字を区別しない）を欠損扱いにします。
- 速度は定義書のm/sを3.6倍しkm/hへ換算します。欠損・非数値・負数・無限大は平均から除外します。
- 緯度経度の欠損・範囲異常は記録しますが、交通手段等の集計対象には残します。
- トリップは「観測日＋DAILYID＋TRIP_RK＋LOGTIME_START＋LOGTIME_END」で重複除去します。
  キーが欠けるポイントはポイント集計だけに含めます。
  同じキーで属性が異なる場合は入力順で最初の値を採用します。
- 所要時間は終点時刻−始点時刻です。不正・負の時間は時間平均から除外しますがトリップ数には含めます。
- 日をまたいで現れる同一移動は別計上となる可能性があります。日別ID数を足しても期間内の実人数にはなりません。
- 交通手段コードは1:航空機、2:新幹線、3:その他鉄道、4:高速道路自動車、5:その他自動車、
  6:船舶、7:自転車、8:徒歩、9:不明です。未定義コードは元の値を保持します。
- 平均速度はポイントを等しい重みで平均します。トリップの平均旅行速度とは異なります。
- ポイント比率は観測頻度に影響されます。交通分担率にはトリップ集計を参照してください。
  ただし推定結果・取得対象の偏りがあり、母集団の交通量・人数への拡大推計は行っていません。
- 距離や個人の移動経路は出力しません。ODは定義書の125mメッシュです。
- `--limit` は対象期間の先頭Nポイントであり無作為抽出ではありません。

ZIPは約2.1GBあり、全件処理には時間がかかります。SQLiteの重複除去用DBに
日別IDとトリップ単位の識別子・始終点メッシュ・時刻が保存されるため、
十分な空きディスクを確保し、出力先のアクセス権を適切に管理してください。
CSVとHTMLは集計結果です。元ZIPの全展開や全件のメモリ読み込みは行いません。
